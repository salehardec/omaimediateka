# Omaimediateka

> English version: [README.md](README.md)

Бар-виджет Omarchy Shell (Quickshell) для **просмотра** фото и видео с
iPhone или Android-телефона, подключённого **USB-кабелем**: кнопка в центре
бара, попап по центру экрана со сеткой превью из `DCIM` и полноэкранным
просмотром.

> Этап 1 — только чтение. Плагин ничего не импортирует на компьютер и не
> удаляет с телефона, не трогает музыку, контакты и прочие файлы.

## Возможности

- **Кнопка в баре** — без телефона `Omaimediateka · —`, с телефоном
  `iPhone 15 Pro · N` / `Android Pixel 8 · N` (N = число фото и видео). Модель
  берётся из `ideviceinfo -k ProductType` (переводится в название модели,
  неизвестный тип показывается как есть) или из MTP/USB-имени; не определилась —
  просто `iPhone`/`Android`. Длинное имя обрезается «…», бар не ломается.
- **iPhone и Android рядом**: попап показывает тип и имя устройства; если
  подключены оба, переключатель в попапе выбирает, какой смотреть (первым
  показывается готовое устройство, при равенстве — iPhone).
- **Сетка** — превью фото и видео из всех папок `DCIM` (`100APPLE`,
  `101APPLE`, …), ленивая генерация миниатюр, кэш на диске.
- **Полноэкранный просмотр** — выбранный кадр почти на весь экран, подпись
  (имя, дата, размер), навигация стрелками; для видео — воспроизведение
  (если доступен QtMultimedia).
- **Сортировка** — по умолчанию новые сверху (по номерам Apple), можно
  переключить на «сначала старые».
- **Фильтр** — живой поиск по имени файла, папке и **содержимому** (родной
  индекс Apple: русские лексемы сцен/OCR, метки сцен и действий из
  `MediaAnalysis` и английские caption'ы, в том числе посегментные),
  с бейджем источника на совпаших ячейках.
- **Экспорт** (на телефоне ничего не меняется): сохранение оригинала в
  `~/Pictures/iPhone` (`Ctrl+S`) или в выбранную папку (`Ctrl+Shift+S`);
  занятые имена получают суффикс ` (1)`, ` (2)` вместо перезаписи. `Ctrl+C`
  кладёт фото в буфер как `image/png` (HEIC декодируется `heif-convert`),
  а видео — текстовым путём.
- **Выбор нескольких**: `Space`, чекбокс или `Ctrl`+клик отмечают ячейки,
  `Ctrl+A` — все видимые; кнопки экспорта работают со всем выделением.
- **Состояния** — «телефон не подключён», «нужно доверие», «нет gvfs-afc»/
  «нет gvfs-mtp», «Android только заряжается или заблокирован» и т.п. с
  понятной инструкцией вместо пустого экрана.

## Требования к системе

Плагин сам систему не меняет. Один раз выполните (нужен `sudo`):

```bash
sudo pacman -S gvfs-afc
sudo systemctl start usbmuxd
```

`usbmuxd.service` статическая: её поднимает udev при подключении iPhone,
поэтому `enable` не требуется — достаточно подключить кабель. Затем
разблокируйте iPhone и нажмите **«Доверять этому компьютеру»**.

Проверка:

```bash
idevice_id -l                       # должен показать UDID
idevicepair -u <UDID> validate      # SUCCESS: Validated pairing
ls "$XDG_RUNTIME_DIR"/gvfs/afc:host=*   # появится DCIM/
```

### Android (MTP)

Нужен пакет `gvfs-mtp` (без root на телефоне и без ADB):

```bash
sudo pacman -S gvfs-mtp
```

Подключите телефон кабелем, разблокируйте его и в шторке откройте
уведомление USB («Зарядка устройства через USB» / «USB для передачи
файлов»), выберите режим **«Передача файлов»** (MTP). В режиме «Только
зарядка» файлы телефона недоступны: попап покажет «Только зарядка» и
подскажет, что нажать. Если телефон спросит разрешение — разрешите доступ.

Проверка:

```bash
gio mount -l | grep -i mtp                                  # телефон в списке
ls "$XDG_RUNTIME_DIR"/gvfs/mtp:host=*/*/                    # DCIM, Pictures, ...
```

Медиа читаются из `DCIM` (включая `DCIM/Camera` и `DCIM/Screenshots`) и
`Pictures` каждого хранилища телефона (внутренняя память и SD-карта, если
есть). Закройте другие программы, держащие MTP-соединение (файловый
менеджер с открытым телефоном): одновременно к нему может обращаться
только один клиент.

Используемые пакеты: `libimobiledevice`, `libusbmuxd`, `usbmuxd`,
`libheif` (`heif-convert`), `ffmpeg`/`ffprobe`, `qt6-multimedia-ffmpeg`,
`wl-clipboard` (`wl-copy`) — для копирования в буфер; `zenity` или
`kdialog` (необязательно) — для «Сохранить как»; `python3` — для поиска по
содержимому (без него остальное работает, ищется только по имени).

## Установка

```bash
./install.sh
```

Затем добавьте виджет в центр бара — `~/.config/omarchy/shell.json`,
секция `bar.layout.center`:

```json
{ "id": "omaimediateka" }
```

И перезапустите шелл:

```bash
omarchy restart shell
```

Вручную — скопировать файлы плагина в
`~/.config/omarchy/plugins/omaimediateka/` (папка создаётся по `id` из
`manifest.json`) и сделать `bin/oma-mediateka` исполняемым.

Удаление: `./install.sh --uninstall`.

## Как это работает

- Доступ к `DCIM` — через **gvfs-afc**: `gio mount afc://<UDID>/` и путь
  `$XDG_RUNTIME_DIR/gvfs/afc:host=<UDID>/`. `gvfsd-fuse` поднимает
  пользовательская сессия, root не нужен, при отключении кабеля путь
  исчезает сам.
- Доступ к Android — через **gvfs-mtp**: `gio mount mtp://<host>/` и путь
  `$XDG_RUNTIME_DIR/gvfs/mtp:host=<host>/<хранилище>/`. Хелпер читает `DCIM`
  и `Pictures` каждого хранилища, скрытое (`.thumbnails`, `.trashed-*`)
  пропускает. MTP через gvfs медленнее AFC, поэтому последний полный
  листинг лежит в `~/.cache/omaimediateka/lists/`: при повторном подключении
  сетка появляется сразу, а свежий обход идёт в фоне (в шапке «обновление…»).
  Превью генерируются по одному из оригиналов, как у iPhone; для постера
  видео файл сначала нужно получить с телефона.
- `bin/oma-mediateka` — единственное место, знающее о бэкенде:
  - `status [iphone|android]` — определяет устройства, доверие/режим
    передачи файлов и монтирование (одна JSON-строка: `state`, `type` =
    `iphone`/`android`/`none`, `name`, `model`, `id`, `roots`, список всех найденных
    `devices`);
  - `list [--cache KEY] <dir>...` — один проход `find` по медиафайлам в одном
    или нескольких корнях (TSV); `list-cached <KEY>` — последний сохранённый
    листинг;
  - `thumb <src> <dst> <kind> [thumb|preview]` — превью в кэш;
  - `meta <src>` — длительность/размеры видео;
  - `names <dir>` / `copy <src> <dst>` — экспорт: список имён и копирование
    оригинала (без перезаписи; суффикс ` (1)`, ` (2)` добавляет интерфейс);
  - `clip-image <src>` / `clip-text <text>` — буфер обмена через `wl-copy`;
  - `pick-dir [start]` — выбор папки (`zenity`, иначе `kdialog`);
  - `index [mount]` — копирует (только чтение) базы поиска Apple и собирает/
    обновляет компактный кэш (инкрементально, с прогрессом);
    для Android отказывает (код 5);
  - `search <query>` — строки `path<TAB>source<TAB>matched` из этого кэша.
- Превью: JPEG/PNG/WebP — `ffmpeg`; **HEIC/HEIF** — `heif-convert`
  (ffmpeg в системе без HEIF); видео — кадр через `ffmpeg`.
- Кэш: `~/.cache/omaimediateka/thumbs/` и `.../previews/`; миниатюры
  генерируются лениво по мере появления ячеек на экране, по одной за раз,
  и не пересчитываются без изменения файла (ключ включает `mtime` и размер,
  а у Android ещё и id устройства, так что одноимённые файлы двух телефонов не
  путаются).
- **Поиск по содержимому**: хелпер копирует `Photos.sqlite` и
  `MediaAnalysis.sqlite` в `~/.cache/omaimediateka/apple-index/` и превращает
  родной индекс Apple «Leo», метки сцен/действий/питомцев из `MediaAnalysis`
  и caption'ы Vision (включая посегментные caption'ы видео) в компактный
  `search.sqlite` (`asset`, `token`, `caption`). Разбор BLOB и
  NSKeyedArchiver-блоба действий — в `bin/oma-mediateka-index.py`.
  Индекс докачивается инкрементально при подключении телефона (или кнопкой),
  поэтому открытие попапа его не ждёт. Русские лексемы ищутся по префиксу
  с отсечением окончаний, caption'ы — по словам, совпадения по имени
  объединяются. Пары Live Photo HEIC+MOV схлопываются в фото, результаты
  ранжируются по числу содержательных источников (метки сцен/действий не
  добавляются при уверенности ниже порога).
- Состояние опрашивается раз в 2.5 с при открытом попапе и раз в 6 с при
  закрытом; отключение телефона сразу переводит интерфейс в «не подключён».

Дизайн-спека: [`docs/superpowers/specs/2026-10-01-iphone-media-plugin-design.md`](docs/superpowers/specs/2026-10-01-iphone-media-plugin-design.md).

## Ограничения

- **Только чтение** с телефона: ничего не удаляется и не меняется на iPhone,
  экспорт лишь копирует оригиналы наружу.
- Экспорт **никогда не перезаписывает**: занятое имя получает суффикс
  ` (1)`, ` (2)`, …
- Сортировка — по номерам Apple (iPhone) или по времени изменения файла
  (Android), а не по EXIF-дате.
- **У Android нет поиска по содержимому**: готового индекса вроде Apple Leo
  на телефоне нет, поэтому попап пишет «поиск по содержимому недоступен», а
  фильтр ищет по имени файла, папке и дате (`2026-10-13`, `13.10.2026`,
  `13 октября`, `октябрь 2026`); кнопка «Обновить поиск» скрыта.
  Распознавание на нашей стороне отложено.
- Android: MTP через gvfs медленный на больших библиотеках (первый листинг
  и каждый постер видео могут занимать время); сканируются только `DCIM` и
  `Pictures`; телефон должен оставаться разблокированным в режиме «Передача
  файлов». «Только зарядка» определяется по USB-идентификатору известных
  производителей Android, поэтому редкую марку покажет как «не подключён».
- **Живые фото** в сетке — два элемента (HEIC и MOV); в выдаче поиска пара
  схлопывается в фото.
- **Поиск по содержимому** опирается на недокументированный индекс Apple:
  покрыто ~99.5 % ассетов; ассеты только в iCloud пропускаются (нет файла);
  обновление iOS может сменить схему — тогда поиск деградирует до фильтра
  по имени/папке. Если iPhone заблокировать или начать звонок во время
  индексации, копирование повторится трижды, а затем в строке статуса
  появится «Нет доступа к телефону: разблокируйте iPhone, завершите звонок и
  повторите»; старый индекс при этом продолжает работать.
- Индекс строится под конкретное устройство в `~/.cache/omaimediateka/` и
  обновляется при повторном подключении; первая сборка копирует ~330 МБ по
  USB (~15 с).
- Один телефон одновременно: если подключены и iPhone, и Android,
  переключатель в попапе (первым показывается готовое устройство). Два
  телефона одного типа — берётся первый найденный.
- `ifuse` не используется; бэкенд изолирован в `bin/oma-mediateka`.

## Тесты

```bash
node test/MediaModel.test.js   # чистая модель: листинг, сортировка, фильтр, поиск, даты Android
python3 test/test_index.py     # сборка кэша: BLOB, действия, пороги, миграция
python3 test/test_android.py   # хелпер на поддельном gvfs-каталоге (телефон не нужен)
bash -n bin/oma-mediateka      # синтаксис хелпера
python3 -m py_compile bin/oma-mediateka-index.py   # синтаксис индексатора
./bin/oma-mediateka status     # запрос без телефона: state=no-device
```

## Структура

```
manifest.json      # id, kinds: bar-widget, entryPoints.barWidget
Panel.qml          # бар-пилюля + попап: сетка, фильтр, просмотр
VideoView.qml      # плеер QtMultimedia (в изоляции)
MediaModel.js      # чистая модель (node-тестируемая)
bin/oma-mediateka  # status | list | thumb | meta | … | index | search
bin/oma-mediateka-index.py  # сборка и запрос кэша поиска по содержимому
install.sh         # установка/удаление
test/              # node-тесты модели, python-тесты индекса и хелпера
docs/              # дизайн-спека, исследование и скриншоты
```
